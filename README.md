# 카드 캐시백

카드사 캐시백 프로모션을 관리하는 2인용 웹앱.
구글 스프레드시트를 DB로 쓰고, GitHub Pages로 배포합니다. (시네마테크/오운완과 같은 구조)

- 내 카드: 보유 카드 정보 + 카드사별 응모 가능 현황 + 해지 금지 기간 표시
- 프로모션: 공고 텍스트/캡처를 AI가 읽어 조건 정리, 내 이력 기준 자격 판정, 후보군, 신청, 결제 진행 관리
- 결산: 연도별로 어느 카드사에서 얼마를 받았는지, 앞으로 받을 예정은 얼마인지
- 아카이브: 끝난 프로모션 총 수령액, 해지한 카드 이력
- 공고 원문은 텍스트와 캡처 모두 보관되어 상세 화면에서 언제든 다시 볼 수 있습니다
- 카드명만 입력하면 AI가 검색해 카드사, 브랜드, 연회비, 전월실적, 혜택, 표지 이미지를 채워줍니다
- 결제 알림을 폰에서 자동으로 흘려보내 최근 사용일을 갱신할 수 있습니다 (갤럭시_결제알림_자동기록.md 참고)

## 설치 (약 15분)

### 1. 스프레드시트 + Apps Script

1. 새 구글 스프레드시트를 만든다 (이름 예: 카드캐시백DB)
2. 확장 프로그램 > Apps Script > 기본 코드를 지우고 `apps-script/Code.gs` 내용 붙여넣기 > 저장
3. 함수 선택창에서 `setup` 선택 > 실행 > 권한 승인
   시트 3개(사용자/카드/이벤트)가 자동 생성됨
4. **사용자 시트에서 아이디, 비밀번호, 이름을 원하는 값으로 수정** (기본값 user1/1234는 반드시 변경)

### 2. Gemini 키 (AI 공고 분석용)

1. https://aistudio.google.com/apikey 에서 무료 API 키 발급
2. Apps Script 왼쪽 톱니(프로젝트 설정) > 스크립트 속성 > 속성 추가
   - 속성: `GEMINI_KEY` / 값: 발급받은 키
3. 키를 넣지 않아도 앱은 돌아가지만, 공고 분석 기능만 "GEMINI_KEY가 설정되지 않았습니다" 오류가 뜹니다.

### 3. 웹 앱 배포

1. Apps Script 우상단 배포 > 새 배포 > 유형: 웹 앱
2. 실행 계정: 나 / 액세스 권한: **모든 사용자**
3. 배포, URL 복사 (**배포 관리의 복사 아이콘 사용**, `/exec`로 끝나야 정상)
4. `js/config.js`의 `APPS_SCRIPT_URL`에 붙여넣기

### 4. GitHub Pages 업로드

1. hyun6500.github.io 저장소에 `card/` 폴더째 업로드 (css, js 폴더 포함 - 폴더째 드래그)
2. https://hyun6500.github.io/card/ 접속, 로그인

## 과거 기록 이관 (일회성)

예전에 다른 시트에 적어둔 캐시백 기록을 한 번에 넣으려면 `apps-script/과거기록_이관.gs`를 씁니다.

1. DB 스프레드시트 > 확장 프로그램 > Apps Script
2. 왼쪽 파일 목록에서 + 를 눌러 스크립트 파일을 새로 만들고 그 파일에 붙여넣기 (Code.gs는 건드리지 않습니다)
3. 파일 위쪽 IMPORT_DATA 표에서 이름, 금액, 날짜를 확인하고 고치기
4. `IMPORT_미리보기` 실행 후 실행 로그 확인
5. 맞으면 `IMPORT_실행`

같은 사용자, 같은 카드사, 같은 이벤트명이 이미 있으면 건너뛰므로 두 번 실행해도 중복되지 않습니다.
잘못 넣었으면 `IMPORT_되돌리기`로 이 스크립트가 넣은 행만 지울 수 있습니다.
이관은 웹앱과 무관하므로 재배포할 필요가 없습니다.

## 결산 탭과 결산 시트

연도별 캐시백 집계를 두 곳에서 볼 수 있습니다.

- 앱의 **결산 탭**: 연도별 총액과 카드사별 내역. 아직 안 받은 예정 금액은 주황색으로 따로 표시됩니다.
  카드사 옆에 사용 중인지 해지했는지, 해지일은 언제인지도 함께 나옵니다.
  두 사람이 함께 쓰는 경우 위쪽 칩으로 사람별 또는 전체를 골라 볼 수 있습니다.
- **결산 시트**: 결산 탭 아래 "구글 시트에도 결산표 만들기"를 누르면 DB 스프레드시트에 "결산" 시트가 만들어집니다.
  스프레드시트 메뉴의 카드 캐시백 > 결산 시트 새로 만들기로도 됩니다.
  누를 때마다 최신 내용으로 다시 쓰므로, 시트에 직접 적은 내용은 지워집니다.

집계 기준은 이렇습니다. 받은 돈은 **돈 들어온 날**의 연도로 잡습니다.
예정 금액은 도전으로 고르고 아직 안 받은 혜택만 세며, 지급 시기 문구에서 연도를 읽고
없으면 결제 마감일 연도로 잡습니다. 고민 중이나 관심없음으로 둔 혜택은 예정에 넣지 않습니다.

## 카드 표지 이미지

카드 표지는 주소만 저장하고 이미지 자체는 어디에도 보관하지 않습니다. 드라이브를 쓰지 않습니다.

- 카드 추가나 수정 화면의 "카드 표지 이미지 주소"에 https로 시작하는 이미지 주소를 넣으면 됩니다.
  카드사 홈페이지나 카드고릴라에서 카드 그림을 길게 눌러 "이미지 주소 복사"한 값을 붙여넣으세요.
- 카드명 불러오기를 쓰면 AI가 이미지 주소도 같이 찾아옵니다. 다만 확실한 주소를 못 찾는 경우가 많아
  비어 있을 때가 잦습니다. 그때는 직접 복사해 넣으시면 됩니다.
- 표지가 있으면 내 카드 탭의 카드 면, 프로모션 카드 헤더, 아카이브 목록에 함께 나옵니다.
- 상대 사이트가 외부 연결을 막고 있으면 이미지가 안 뜹니다. 그럴 땐 자동으로 카드사 색 그라디언트로 돌아가니
  화면이 깨지지는 않습니다.

## 카드 정보 불러오기

내 카드 탭의 카드 추가나 정보 수정 화면에서 카드명을 적고 "불러오기"를 누르면,
Gemini가 구글 검색으로 카드사 홈페이지와 여신금융협회 공시를 찾아 후보를 보여줍니다.
고르면 카드사, 브랜드, 연회비가 채워지고 전월실적과 혜택은 메모로 들어갑니다.

연회비와 실적 조건은 자주 바뀌므로 검색으로 확인되지 않은 항목은 "추정" 표시가 붙습니다.
저장 전에 카드사 페이지에서 한 번 확인하세요.

## 사용 흐름

1. **프로모션 탭 > 공고 분석하기** 에서 이벤트 페이지 텍스트를 붙여넣거나 화면 캡처를 올립니다 (둘 다 가능)
2. AI가 카드사, 혜택, 자격 조건, 유의사항을 정리하고 내 이력과 대조해
   **응모 가능 / D-며칠 후 가능 / 대상 제외**를 판정합니다
3. 괜찮으면 **후보군에 담기**
4. 실제로 응모를 마쳤으면 상세에서 **전화 상담 확인을 체크하고 신청 완료 처리**.
   참여 중으로 옮겨지고 내 카드 탭에 카드가 자동 등록됩니다
5. 혜택마다 **도전 / 고민 중 / 관심없음**을 고릅니다.
   도전으로 고른 것만 카드에 펼쳐지고 홈의 "들어올 돈"과 마감 알림에 반영됩니다.
   나머지는 태그로만 접혀 남으니 잊히지 않습니다
6. 도전한 혜택은 진행바, 남은 금액, 결제 마감 D-day, 유지해야 하는 것,
   조건을 채우려면 확인할 일 체크리스트가 계속 표시됩니다. 체크는 누르는 즉시 저장됩니다
7. 결제할 때마다 혜택별 **사용 금액**을 업데이트합니다
8. 캐시백이 들어오면 **실제 지급일과 금액**을 입력합니다. 카드사별 수혜 이력에 자동 반영됩니다
9. 다 받았으면 **모두 받았어요, 아카이브로**
10. 카드를 정리할 땐 내 카드의 **해지 금지 날짜**를 먼저 확인하세요 (어기면 캐시백 회수)

공고에서 채널(토스, 네이버페이 등)을 찾지 못하면 분석 결과에서 직접 고르게 물어봅니다.
이미 담아둔 이벤트와 같은 건으로 보이면 (같은 카드사이면서 응모 마감일이 같거나 이름이 겹치면)
새로 담을지 기존 것에 덮어쓸지 물어봅니다. 덮어쓰기를 골라도 이미 입력한 사용 금액,
실제 지급 내역, 상담 확인 표시, 저장된 캡처는 그대로 유지됩니다.

## 공고 원문 보관

- 프로모션 상세 아래 "공고 원문 다시보기"를 열면 담을 때의 원문 텍스트와 캡처가 그대로 나옵니다.
- 원문 위에는 핵심 요약 카드가 화면에 고정됩니다. AI 요약문, 혜택별 조건과 금액, 자격 조건, 응모 마감이 한눈에 들어오고,
  긴 원문을 스크롤해도 따라 내려오기 때문에 원문과 요약을 대조하며 읽을 수 있습니다.
- 캡처를 올린 경우 텍스트를 붙여넣지 않았더라도, AI가 옮겨 적은 전문이 원문으로 함께 저장됩니다.
- 캡처 이미지는 내 드라이브의 `카드캐시백_공고캡처` 폴더에 저장되고, 앱에서 보이게 하려고 링크 공개(보기 전용)로 설정됩니다.
  주소를 아는 사람만 볼 수 있고 검색에는 노출되지 않지만, 공개가 마음에 걸리면 Code.gs 상단의 `SAVE_SHOTS`를 `false`로 바꾸세요.
  그러면 캡처는 저장하지 않고 판독한 원문 텍스트만 남습니다.
- 이 기능이 생기기 전에 담은 기록에는 "저장된 원문이 없습니다"가 표시됩니다.

## 알아둘 것

- 자격 판정은 내가 앱에 기록한 이력 기준입니다. 카드사 전산의 무실적, 수혜이력과 다를 수 있으니
  응모 전 전화 상담 확인을 권장합니다 (앱에도 체크 항목이 있는 이유).
- 공고에서 조건을 못 읽으면 기본값(무실적 6, 수혜제한 12, 해지대기 6, 회수방지 12개월)으로 판정하고
  "미확인(기본값)"으로 표시합니다.
- 두 사용자의 데이터는 이름 기준으로 분리 표시됩니다. 시트 하나를 같이 씁니다.
- 간단 인증입니다: 통신은 HTTPS지만 비밀번호가 시트에 평문 저장되므로,
  다른 곳에서 쓰는 비밀번호를 재사용하지 마세요.

## AI 호출 한도 (429 오류)

429는 카드명이나 공고 문제가 아니라 Gemini 쪽에서 요청을 거부한 것입니다. 두 종류를 구분해야 합니다.

**웹 검색만 429인 경우 (흔함)**
구글 검색 그라운딩은 결제가 연결된 프로젝트에만 할당됩니다. 결제를 안 걸어둔 프로젝트에서는
기다려도 풀리지 않습니다. 이때 앱은 자동으로 검색 없이 한 번 더 시도하고,
결과에 "웹 검색이 막혀 있어 AI가 아는 범위로만 찾았습니다"라고 알려줍니다.
이 모드에서는 이미지 주소를 채우지 않고 모든 값이 추정으로 표시되니 카드사 페이지에서 확인하세요.
검색까지 쓰고 싶으면 해당 프로젝트에 결제를 연결하면 됩니다. 이 앱 사용량이면 비용은 미미합니다.
공고 분석은 검색을 쓰지 않으므로 이 상황에서도 정상 작동합니다.

**일반 호출까지 429인 경우**
무료 등급의 하루 허용량을 다 쓴 것입니다.

- 한도는 API 키가 아니라 **구글 클라우드 프로젝트 단위**입니다. 키를 새로 만들어도 같은 프로젝트면 늘어나지 않습니다.
- 시네마테크 앱과 같은 키를 쓰고 있다면 티켓 판독 호출과 한도를 나눠 쓰게 됩니다.
  분리하려면 AI Studio에서 **새 프로젝트**를 만들고 그 프로젝트의 키를 이 앱에 넣으세요.
- 초기화는 태평양 시간 자정, 한국 시간으로 오후 4시(서머타임 기간) 또는 오후 5시입니다.
- 지금 내 한도와 사용량은 https://ai.dev/rate-limit 에서 확인합니다.
- Apps Script 편집기에서 `checkGemini` 함수를 실행하면 모델별로 지금 살아 있는지, 한도에 걸렸는지
  실행 로그에 찍힙니다. 검색 기능이 붙은 호출과 아닌 호출을 따로 확인합니다.
- 한도가 계속 부족하면 해당 프로젝트에 결제를 연결하는 것이 확실합니다. 이 앱 사용량이면 비용은 미미합니다.

같은 카드명을 다시 검색하면 6시간 동안은 저장된 결과를 돌려주므로 한도를 다시 쓰지 않습니다.

## 드라이브 권한 오류

"DriveApp.getFoldersByName을(를) 호출할 수 있는 권한이 없습니다"가 뜨면,
캡처 저장 기능이 추가되기 전에 승인해둔 상태라 권한이 빠져 있는 것입니다. 재배포만으로는 해결되지 않습니다.

1. Apps Script 편집기에서 `authorizeDrive` 함수를 선택하고 실행
2. 권한 요청 창에서 허용
3. 배포 > 배포 관리 > 연필 > 새 버전 > 배포

캡처 저장을 안 쓰실 거면 Code.gs 상단의 `SAVE_SHOTS`를 `false`로 두셔도 됩니다.
어느 쪽이든 프로모션 등록 자체는 정상 진행되고 원문 텍스트는 저장됩니다.

## 재배포가 실제로 됐는지 확인하기

Apps Script는 **저장과 배포가 별개**입니다. 편집기에서 함수를 직접 실행하면 저장된 최신 코드가 돌지만,
앱이 부르는 웹앱 주소는 마지막으로 배포한 버전의 코드를 씁니다.
그래서 코드를 고치고 저장만 하면 편집기에서는 새 코드가, 앱에서는 예전 코드가 도는 상태가 됩니다.

Code.gs를 고친 뒤에는 매번 이렇게 하세요.

1. 편집기에 새 코드를 붙여넣고 저장
2. 우상단 **배포 > 배포 관리**
3. 기존 배포 오른쪽의 **연필(수정)** 아이콘 클릭
4. 버전 드롭다운에서 **새 버전** 선택
5. **배포** 클릭

주소는 그대로 유지되므로 config.js는 건드릴 필요 없습니다.
새로 배포를 만들면 주소가 바뀌니 "새 배포"가 아니라 기존 배포를 수정하세요.

확인 방법은 두 가지입니다.

- 앱 화면 맨 아래에 `v1.5.3 (서버 1.5.3)`처럼 앱 버전과 서버 버전이 함께 나옵니다.
  둘이 다르면 빨간 글씨로 재배포하라고 알려줍니다.
- 웹앱 주소를 브라우저로 열면 `{"ok":true,"ping":"card-cashback","server":"1.5.3",...}`가 나옵니다.

## 문제 해결

- 화면이 안 뜸, js/config.js의 URL이 `/exec`로 끝나는지, 따옴표가 닫혔는지 확인
- "알 수 없는 action", Code.gs 수정 후 **새 버전으로 재배포** 누락
- 분석 실패, 스크립트 속성 GEMINI_KEY 확인
- 진단: `{APPS_SCRIPT_URL}` 주소를 브라우저로 열면 `{"ok":true,"ping":"card-cashback"}`가 떠야 정상
